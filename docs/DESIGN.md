# 智能拼音 · 设计说明

本文说明输入法各部分如何对应需求 1–7，以及每一部分是如何验证的。评测数字见 `README.md` 与 `docs/RESULTS.md`。

## 总体结构

```
按键 ──► 音节图（容错） ──► 词图 ──► n-gram 束搜索 ──► 候选集合（封闭选项）
                                                     │
                     前文 + 候选 ──► 小模型（Qwen3-0.6B-Base, Q8）批量打分：log P(候选 | 前文)
                                                     │
            特征：n-gram、读音、误触代价、简拼/未完成、词数、小模型、个人模型、上下文记忆
                                                     │
                                    对数线性决策层 → softmax 概率 → 首选 / 置信度
                                                     │
               上屏 ──► Learner 观察保留 / 删除 / 重输 / 改选 ──► 个人模型、记忆、误触模型、信任权重
```

代码位置（`Sources/PinyinEngine`）：

| 模块 | 文件 | 作用 |
|---|---|---|
| 音节表 | `Syllables.swift` | 415 个无调音节、字母 trie、前缀/声母集合 |
| 误触模型 | `TypoModel.swift` | 键盘邻接、7 类编辑的代价（nats），按用户实际纠错自适应 |
| 音节图 | `SyllableGraph.swift` | 精确音节、末尾未完成音节、简拼、以及“恰好一处误触”的音节读法 |
| 词典 | `Lexicon.swift` | 92.8 万词条（rime-ice，含 4 万生僻字），音节序列 trie，mmap 二进制 |
| n-gram | `NGram.swift` | 改进 Kneser-Ney 词二元模型（9.7 亿字语料，2700 万二元组），mmap |
| 词图 / 解码 | `Lattice.swift`, `Decoder.swift` | 词图、束搜索、同音同跨度替换（保证“智能/只能”这类选项都在候选里） |
| 小模型 | `NeuralScorer.swift` | llama.cpp + Metal；前文常驻 KV cache，候选按 token 前缀树一次批量前向 |
| 调度 | `NeuralService.swift`, `Composer.swift` | 最新优先的异步打分、显示/上屏时机策略 |
| 个人化 | `PersonalModel.swift`, `UserWords.swift`, `Learner.swift`, `PersonalStore.swift` | 个人词频/二元、上下文记忆（kNN）、用户词（人名、新词）、行为解释、持久化与遗忘 |
| 输入法外壳 | `Sources/SmartPinyin` | InputMethodKit 控制器、候选窗、全角标点、隐私名单 |

## 1. 根据上下文理解意图

- **候选生成**：n-gram 束搜索给出整句 N-best，再对前几条路径的每一段做“同跨度替换”（例如把“只能”换成“智能”），保证语境要判断的对手一定在候选集里。
- **概率决策（借鉴 Jev 的形式）**：候选集合就是事先写好的“选项”，小模型不生成文本，只在一次并行前向里给每个选项打出 `log P(选项 | 前文)`。它和其他特征一起进入对数线性层，softmax 之后得到每个候选的概率。首选的概率就是置信度，学习信号的权重也用到它。
- **效率**：前文 token 常驻 KV cache（序列 0），上屏后增量追加；候选按 token 前缀树组成一个 batch，共享前缀只算一次（llama.cpp 的多序列 id + unified KV）。
- 权重由 `tools/fit_weights.py` 在 8000 个模拟打字样本上用条件 logit 拟合。

## 2. 容忍误触

- 在音节层面枚举“恰好一次编辑”的读法：重复键、多按邻键、漏键、按错邻键、相邻交换（非邻键的替换/插入代价高、收益低，默认关闭）。
- 误触代价是噪声信道的 `-log P(按键 | 意图)`，与语言/小模型分数一起比较。所以 `duooyin` 在“读音”语境下会恢复成“多音”，而“多哦音”被小模型判为几乎不可能。
- **防误纠**：修正读法必须比最好的“照打字面”读法高出 `typoGuard`，才能排到第一。这个门槛由拟合决定（默认 1.0 nats），再按用户实际行为自适应：用户撤销自动修正时抬高，修正读法因门槛落选、用户却手动改成它时降低。用户习惯性的误触（例如经常把 uo 打成 ou）需要的门槛更低。

## 3. 无监督自动学习（Learner）

输入法维护一段“最近由我上屏的文本”（run）。退格从 run 末尾删字，删除后的新上屏构成替换，替换完成后对这段经过（episode）分类：

| 观察到的行为 | 判定 | 学到什么 |
|---|---|---|
| 删掉刚上屏的词，用**相同拼音**重新得到别的字 | 选词错误（reselection） | 上下文记忆：该语境下新字 +、旧字 −；信任权重微调 |
| 删掉后重新输入的**按键只差 1–2 处**编辑 | 误触纠正（typoCorrection） | 误触模型：记住这类编辑与具体键对；必要时放宽门槛 |
| 自动修正后，被删掉并按原键重输出字面结果 | 误纠（wrongCorrection） | 抬高防误纠门槛 |
| 删掉后写了拼音、意思都不同的内容 | 改写/改主意（rewrite） | **不**判断旧文本对错，只撤回它的正向计数 |
| 删掉后没有再写 | 撤回（retraction） | 只轻微撤回正向计数 |
| 在候选里明确选了非首选 | 明确选择 | 记忆 +/−、信任权重微调 |
| 分几次选字拼出一段文本，或从很靠后的位置选出一个词，而引擎自己得不到它 | 新词（见第 4 节“用户词”） | 立即记为用户词 |
| 上屏后在窗口期内（25 秒）没被删 | 保留（kept） | 弱正信号，权重 0.3–0.8，首选越没把握权重越高 |

时间也参与判断：删除发生得越晚，越可能是改写，权重从 1.0 降到 0.25。光标跳走、切换应用、Cmd 组合键等无法跟踪的情况一律视为“断开”，不做推断。

在模拟中（带噪声的用户：约 3% 概率改写正确文本），Learner 对“重打/改写”的分类与真实情况基本一致（6000 段中 302 次重打 → 209 选词 + 78 误触 + 13 误纠；178 次改写 → 177 判为 rewrite）。

## 4. 个人文本持续适应

- **个人语言模型**（`UserLM`）：记录保留文本的词与二元计数，与基础模型比较“观察次数 vs 期望次数”后给出加分。某个词用得多，只在它符合前后搭配时加分；基础模型认为常见、而用户长期回避的词（例如某位用户习惯写“卷的太厉害”而不用“得”）会得到轻微减分；罕见词不受影响。
- **上下文记忆**（`ContextMemory`）：只记录“有竞争”的片段，即同一拼音下用户选择与其他读法不同的那几个字，按音节序列存储，并附带上下文特征（前 16 字的字与字对、应用）。打分时对候选的每个片段做 kNN 投票，与当前语境越像，票越重。
- **用户词**（`UserWords`）：上面两项只能给**已经在候选里**的读法加减分。人名不一样：“林霁雯”不是词库里的词，“霁”在 ji 的所有字里排在词图每个跨度 16 个词的配额之外，所以束搜索永远生成不出这个候选，记忆里记了也没有东西可以加分。
  - **什么时候记**：用户明确选出的文本（分几次选字拼出来，或选了非首选）里，引擎首选读错的那几个词会被单独检查：只用这段拼音、同样的前文让引擎再解一次。
    - 引擎根本得不到这段文本（含生僻字的名字、排在配额外的词或单字）→ 记为用户词。
    - 引擎能得到，但这段文本是一串单字，而且比它自己的首选低 2 nats 以上（“王思雨”被读成“王死于”）→ 也记。未登录词在引擎眼里就是一串互不相关的单字，这是新词的典型形态。
    - 引擎能得到，而且是它认识的词或由这些词组成的短语（只能 / 智能、她的画 / 他的话）→ 不记，仍然交给按语境投票的记忆，避免一次选择在所有语境里生效。
  - **记什么**：只错了一半的名字会连同旁边的单字一起记。错的是“霁雯”，前面的“林”是个不常用的单字词，就同时记“霁雯”和“林霁雯”；常用字（的、和、说）不算，所以“林霁雯说”只会记到“林霁雯”。
  - **怎么用**：用户词是词图里的一条普通词边（id 在词库之上），和词库词一样支持整句解码、末尾未完成音节、简拼和一处误触，不受跨度配额限制。基础 n-gram 没有它的概率，用 `-11 + ln(次数)` 代替（相当于一个中低频词），个人特征再加 `3 + ln(次数)`（次数按 0.25–20 截断）。
  - **效果**（教一次之后，小模型排序，20 种不同前文）：测了四个词，其中三个是真实的人名和地名，这里不写出来。“王思雨”、一个含生僻字的人名和一个商场名 20/20 排第一；另一个含生僻字的人名 19/20，唯一的例外是有一种前文明显指向一个同音的常见短语，这时仍给出那个短语。和常用同音词撞车时由语境决定：只教过一次的“石室”在 20 种前文里有 8 种排第一，其余仍是“实施”“事实”“试试”；这时手动选一次别的词，它的计数减 0.5，排名随之下降。
  - **撤销**：刚教完就把它删掉，不算数（只删后面的字不影响前面的名字）。被当作首选给出后又被删掉、用同样拼音换成别的，计数减 1，减到 0 就忘掉。首选里的用户词没被采用而是手动选了别的，计数减 0.5。
  - **旧数据**：旧版本的个人数据里，这些名字已经在上下文记忆中（只是用不上）。第一次加载时会把其中“不是词库词、引擎自己解不出来”的文本转成用户词，只做一次（约 0.4 秒）。
- **误触习惯**（`TypoModel`）：按编辑类型和具体键对的次数做贝叶斯更新。
- **信任权重**：只在线微调“个人模型”“记忆”两项的权重（带 L2 回拉），基础权重不动，偶发的奇怪行为因此不会拖垮通用准确率。
- **遗忘**：个人计数和用户词半衰期 120 天，记忆 90 天，习惯改变后模型能跟上。
- **存储**：`~/Library/Application Support/SmartPinyin/personal.json`，保存词 id 计数、哈希后的上下文特征和统计量；文本只有两种：记忆里有争议的那几个字，以及用户词本身（文本 + 拼音）。不保存成段的原文。菜单里可以暂停学习或一键清除。

## 5. 立刻按空格的体验

- 每次按键：快速路径（音节图 + 词图 + n-gram + 个人特征）同步完成，中位数 1.4 ms、p95 4 ms。随后把候选交给小模型队列，“最新优先”，没开始的旧任务直接丢弃。
- **候选窗显示**：先等小模型最多 45 ms（小模型本身约 12–16 ms），拿到结果就直接显示智能排序；超时才显示快速排序。这样在人能读到之前就已经是最终排序。
- **不突变**：列表显示超过 160 ms，或用户已经在移动高亮，就不再重排。
- **按空格**：如果当前显示的就是本次输入的智能排序，直接上屏；否则最多阻塞等待到“最后一次按键后 90 ms”，拿到这次输入的智能首选再上屏（实测几乎从不需要等）。上屏后绝不自动替换。
- 上屏后立即在后台预填新的前文 KV，下一次输入的第一个键就不用付前文的成本。

## 6. 模型

- Qwen3-0.6B-Base（0.6B），GGUF Q8（640 MB），llama.cpp Metal 后端（GPU）。还比较过 Qwen2.5-0.5B、Qwen3.5-0.8B、Qwen3-1.7B，详见 RESULTS.md。Q6_K 在没有前文时会扭曲判断，所以用 Q8。
- 融合层带有“前文长度”交互项：没有前文时更依赖 n-gram 和词频，前文越长越信任小模型（短前文首选准确率 +0.8 个百分点）。
- 输出的是候选上的概率分布，不生成任何自然语言；输入法最终仍然只输出你要的中文。
- 模型没加载好（首次安装后编译 GPU 内核约 13 秒）时，自动退回 n-gram，照常可用。

## 7. 如何验证

- `stbench eval`：留出语料上的模拟打字（上下文 + 1–4 个词的块 + 30% 误触）。
- `stbench latency`：在真实时间下按人类节奏回放按键（包括中途退格重输），经过与输入法相同的 Composer 与异步模型服务，统计空格时是否用上智能首选、等待时间、以及已可读列表是否被重排。
- `stbench personalize`：用一个真实用户（V2EX 用户历史帖子，不在任何训练数据中）前 70% 的文本当作“日常使用”，模拟人的采纳、选词、删改、改主意，经过同一个 Learner 学习，再在后 30% 上评测，同时检查通用文本没有退化。
- `swift test`：解析、编辑分类、Learner 行为判定、Composer 流程、人名 / 新词学习（教一次即首选、句中、删除后撤销、存取、旧数据迁移）的单元测试。
