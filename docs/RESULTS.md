# 评测结果

所有数字都来自 `stbench` 在**留出数据**上的测试：测试语料不参与 n-gram 统计和权重拟合；模拟用户的历史帖子也不在任何训练数据中。复现命令见 README 的“开发”一节。

## 1. 首选准确率、误触恢复、误纠（需求 1、2）

测试集：3000 个模拟打字块，来自维基、知乎、V2EX、FineWeb-Edu 中文的留出文档。每块 1–4 个词、带真实前文，其中 30% 注入一处误触（重复键、多按邻键、漏键、按错邻键、相邻交换）。

| 配置 | 首选准确率 | 前三 | 干净输入首选 | 误纠率（干净输入被改错） | 误触恢复 |
|---|---|---|---|---|---|
| 只用 n-gram + 词典 | 85.0% | 92.4% | 87.9% | 1.0% | 78.6% |
| **+ 小模型概率决策（发布配置）** | **91.3%** | **95.9%** | **93.3%** | **0.1%** | **86.7%** |

- 候选召回率（正确答案在候选中）97.5%。
- 分类型恢复率：重复键 93.3%、多按邻键 90.4%、按错邻键 91.1%、漏键 82.8%、相邻交换 67.2%。
- 需求里的例子：
  - “我想开发一个 + zhineng”→ 智能（0.99）
  - “时间不够，我 + zhineng”→ 只能（0.98）
  - “讨论汉字读音时 + duooyin”→ 多音
  - “分不清 + sm”→ 什么（0.91）

## 2. 空格时是否已有智能首选（需求 5）

`stbench latency` 按人类节奏逐键回放 300 段输入，其中每 7 段有一次中途退格重打。回放走的是与输入法相同的 Composer 和异步模型服务，最后一个字母之后立刻按空格。

| 打字节奏（按键间隔 / 最后一键到空格） | 用上智能首选 | 空格等待 p99 | 最长等待 | 可读列表被重排 |
|---|---|---|---|---|
| 从容 150 ms / 100 ms | 100% | 0 ms | 0 ms | 0 |
| 正常 110 ms / 70 ms | 100% | 0 ms | 0 ms | 0 |
| 很快 70 ms / 40 ms | 100% | 9.3 ms | 11.6 ms | 0 |

- 每次按键的快速路径中位数 1.8 ms、p95 4.7 ms；小模型打分中位数 17 ms。
- 真实使用（你试用期间的日志）：300 次上屏，98.7% 用上智能首选（前 4 次是模型加载前），空格等待 0 次。

## 3. 个人化学习（需求 3、4）

`stbench personalize`：模拟一位真实 V2EX 用户长期使用。这些帖子不在任何训练数据中。前 70% 当日常输入（6000 段），模拟人的真实行为：
- 首选对了就按空格；
- 看到想要的词就点选；
- 有时顺手先上屏，发现不对再删掉重打；
- 约 3% 的时候与输入法无关地删掉重写（改主意）。

学习全部经过同一个 Learner。之后在该用户后 30% 的文本上评测。

| | 学习前 | 学习后 |
|---|---|---|
| 该用户自己的文本（800 段） | 92.8% | 93.1% |
| 该用户 + 习惯性误触（常把 uo 打成 ou，两者都是合法拼音） | 91.2% | **92.5%** |
| 其中习惯性误触的恢复率 | 69.0% | **85.7%** |
| 通用测试文本（检查个人偏好没有“到处都排第一”） | 91.3% | 91.3% |

- Learner 对行为的判定和模拟中的真实情况基本一致：6000 段中 302 次“删掉重打”，判为选词错误 209、误触 78、误纠 13；178 次“改主意”，177 次判为改写，没有被当成错误去学。
- 学到的习惯是可见的：u↔o 交换的误触代价从 5.2 降到 3.3；这位用户习惯写“卷的太厉害”（而不是“得”），学习后也能正确给出。
- 个人词汇带来的提升不大（+0.3~0.5 个百分点）。原因是这位用户留出文本里的剩余错误，大多（30 个里 27 个）根本没在他的历史里出现过，无从学起。误触习惯这类有规律的行为，学习效果明显。

## 4. 模型选择（需求 6）

同一批候选集合（590 个），比较不同小模型作为“判断者”的能力（`tools/compare_judges.py`，2 折交叉验证）：

| 模型 | 只看小模型 | 与其他特征融合 | 输入法内每次打分 |
|---|---|---|---|
| **Qwen3-0.6B-Base（发布）** | 82.5% | **93.6%** | 17 ms |
| Qwen3.5-0.8B-Base | 80.5% | 92.9% | —（混合架构，未接入） |
| Qwen3-1.7B-Base（参照，超出零点几 B） | 86.4% | 94.1% | 39 ms（p99 76 ms） |

在完整测试集上，1.7B 只比 0.6B 高 0.3 个百分点，但速度慢 2.4 倍、内存多 1.8 GB，所以不采用。

量化方面：Q8、Q6_K 与原始 f16 的整体准确率相同（91.1–91.3%）。但 Q6_K 在**没有前文**时会明显扭曲判断，例如把“写上学号”排到“协商学好”后面，而 Q8 与原始精度一致。所以发布用 Q8（640 MB）。

## 已知局限

- 前文很短时，小模型对“气话/企划”“学号/学好”这类同音词的语义判断有限；纠正一次后，上下文记忆会记住。
- 候选窗和图标是照系统输入法仿制的，细节如果有差异，需要对照截图调整。
- 部分应用不向输入法提供光标前的文本，这时只能用输入法自己记录的最近上屏内容当前文。菜单里的统计会显示有多少次拿到了应用的前文。
